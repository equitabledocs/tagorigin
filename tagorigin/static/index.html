Is this PDF really accessible, or just tagged?

Authoring tools like Adobe InDesign, Microsoft Word, and Apple Pages put tags into PDFs automatically on export. Those tags routinely fail accessibility standards. A properly remediated PDF has been opened by a dedicated accessibility tool and edited with human intent. tagorigin tells you which one you have.

Why this matters

Tagged is not the same as accessible

A tagged PDF has a structure tree inside it. Many people, including experienced procurement officers and disability services staff, see a tag tree in Adobe Acrobat and conclude the document is accessible. That conclusion is wrong often enough to be the single most common misconception in document accessibility work. Tags can be present, complete, and still useless to a screen reader user.

How tags land in PDFs without human review

There are two routes:

  1. Authoring tool export. Adobe InDesign, Microsoft Word, Apple Pages, Google Docs, and LibreOffice all add tags when you export a PDF. The tags reflect the source document's styles. If the source was not styled carefully, the tags carry those problems straight into the PDF.
  2. One-click autotag. Acrobat Pro's "Autotag Document" menu, PDFix in autotag mode, Foxit's autotag, and Word's built-in accessibility-check auto-fix all add tags by inferring structure from the page's appearance. No person reviews the result.

Both routes commonly produce the same defects: generic alt text such as "image" or "figure", numbered lists tagged as plain paragraphs, reading order that follows text-frame placement instead of the visual layout, table headers with no scope attribute, and decorative images that screen readers announce as content.

What a real remediation pass involves

A remediated PDF has been opened in a tool that lets a person edit the tag tree directly: Adobe Acrobat Pro's Touchup Reading Order, PDFix's interactive editor, CommonLook, axesPDF, or NetCentric. A person has written meaningful alt text, applied list structure, set scope on table headers, fixed reading order, and marked decorative content as artifacts. That work takes time and judgement. It is not a button press.

What goes wrong when nobody knows the difference

For a student using a screen reader, an autotag-only PDF is often unreadable. Headings that should let them skim are missing. Figures announce as "image" instead of describing what the diagram shows. Tables read across cells without telling them which row or column they are in. The document exists on the screen but cannot be read.

For an institution, the misconception is expensive. A vendor can charge full remediation rates and deliver an autotag pass. The tag tree will look full in Acrobat. The delivered file will still fail in the hands of the students it was meant to serve. tagorigin shows you which one you have, and which one you paid for.

How it works

tagorigin reads the PDF's metadata and structure tree, runs a set of signals across both, and assigns one of five classifications. The central design principle: metadata tells you which tool touched the file; structural quality tells you whether a human reviewed the tags. When they disagree, structure wins.

UNTAGGED

No structure tree. Likely a scanned PDF. Treat as raw input. Run OCR plus tagging before any accessibility work.

AUTO_TAGGED

Tags exist but came from automatic processes only. InDesign export, Word export, or tool-level autotag. No human review of the tags.

LIGHTLY_REMEDIATED

Some human touch detected. Lists or alt text partially fixed, but the work is incomplete.

REMEDIATED

Deliberate full remediation pass. Proper list semantics, meaningful alt text, scoped table headers. Likely meets PDF/UA in substance.

WELL_REMEDIATED

All of the above plus advanced markers. PDF/UA conformance declared, language at span level, complete StructParents.

Who uses tagorigin

Universities and disability services

Evaluate accessibility vendors before signing. Audit existing document libraries. Prepare for ADA Title II 2026.

Educational publishers

Pre-flight check on InDesign exports before sending to remediation vendors. Self-assess template quality. Avoid paying for autotag passed off as remediation.

Government agencies

Section 508 compliance verification. Procurement audits. Public document inventory grading.

Remediation teams

Internal QA on your own output. Vendor-to-vendor comparison on the same source files. Catch regressions where a remediation tool degraded the original.

Privacy and data handling

Files uploaded to this site are processed in memory and the temporary file is deleted immediately after classification. We do not store the PDF, do not log its contents, and do not transmit it to any third party (except optional vision API calls if you enable them via the CLI; the public web form does not use vision).

For sensitive documents we recommend installing tagorigin locally and running it via the command line. The tool is released under the Apache 2.0 licence. See github.com/equitabledocs/tagorigin.
